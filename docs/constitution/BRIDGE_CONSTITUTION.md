# Bridge Constitution v1

## Core Principles

1. Purpose First
2. Core First
3. Assessment First
4. Release Gate First
5. Technical Ownership
6. Project Context Isolation
7. Knowledge Synchronization

### Assessment First
Every task starts with an assessment of the existing implementation. Reuse and extend existing components before creating new ones. Parallel implementations are forbidden unless the assessment proves they are necessary.

### Release Gate First
A task is complete only when every required backend and frontend release gate passes.

### Technical Ownership
Codex owns technical execution and may stop only when a genuine business decision is required.

### Project Context Isolation
Bridge and every managed project keep separate contexts. Codex always works in the context of the selected repository.

### Knowledge Synchronization
Every sprint task ends with an AKB (project knowledge base) update. Code, architecture and documentation must remain synchronized before a task is considered Ready for Owner Review.

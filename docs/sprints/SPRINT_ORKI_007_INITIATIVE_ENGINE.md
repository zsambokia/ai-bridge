# Sprint ORKI-007 - Initiative Engine

**Status:** PASS — READY FOR PRODUCT OWNER REVIEW
**Epic:** Orki Cognitive Operating System
**Authority:** Product Owner autonomous Factory Development Mode directive, 2026-08-02
**Prerequisites:** ORKI-001 through ORKI-006 Release Gates PASS; Executive Checkpoint B issued

## Objective

Prove that Orki proactively derives bounded, explainable and dismissible
initiative observations from project-scoped Cognitive State. The capability
must identify a relevant risk, opportunity, inconsistency, duplication, reuse
candidate, missing evidence, or simplification without a Product Owner asking
for it.

## Scope

- Add a revisioned, project-isolated initiative artefact with priority,
  evidence links, rationale, confidence, category, and dismissible lifecycle.
- Derive observations only from structured Cognitive State projections; never
  search or promote conversation transcripts as working memory.
- Apply deterministic prioritisation and rate limiting so advice guides rather
  than interrupts or recreates questionnaire behaviour.
- Prove proactive risk/opportunity detection, explainability, correction or
  dismissal, project isolation, transcript separation, and absence of plan,
  governance, delivery, or execution side effects.

## Explicit exclusions

- No approval, scope acceptance, contract, work creation, delivery, governance
  action, or execution authority.
- No unbounded repository scanning, UX redesign, or accepted AKB publication.

## Release Gate

PASS requires focused and full backend tests, browser E2E, schema and static
checks, executable proactive-capability evidence, independent assessment,
self-critique, and synchronized ADR, architecture, AKB, roadmap, and Factory
record. A green suite without a demonstrated unsolicited state-derived insight
is a FAIL.

## Release Gate result

All required gates pass in the final repository state. The independent
[assessment](../evidence/sprint-orki-007-initiative-engine-20260802/ASSESSMENT.md)
proves a normal Factory Chat turn produces a bounded, explainable,
state-derived observation without a Product Owner request and without creating
a plan, governance action, or execution authority.

## Product Owner acceptance and maturity boundary

The Product Owner accepted ORKI-007 Engineering Acceptance, Operational
Acceptance and Initiative Engine capability at DCMI **66/100**. This accepts
the current capability as **Level 1 — Observation**, not as the completed
initiative vision. The later maturity path is Recommendation, Alternative
proposal and Cross-project strategic initiative. Each later level requires its
own bounded Sprint and independent behavioural Release Gate; no further
implementation authority is inferred from this accepted Sprint.

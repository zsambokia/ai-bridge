# Diagram 10 — Knowledge & AKB

## Purpose

Defines AKB as a living graph of versioned Knowledge Objects and Context
Packages as immutable, reproducible references to governed knowledge.

## Responsibility and ownership

AKB owns Knowledge Objects and their publication. Knowledge Lifecycle Management
detects changes, plans updates, synchronizes representations, measures
freshness, publishes versions, and invalidates stale Context Packages.

## Contracts, lifecycle, and rules

Knowledge Object identity is stable; versions are immutable after publication.
Context Builder puts Knowledge References, not copied knowledge, into Context
Packages. Logs, sessions, request data, and execution state are not Knowledge
Objects.

## Failure, evidence, and open questions

Drift may be temporary but must be detectable, measurable, and recoverable.
Stale Context use requires explicit policy and Evidence. Physical graph/vector
technology remains undecided.

## Related authority and maintenance

AKB Knowledge Object & Lifecycle Constitution and Article III Context rules.
